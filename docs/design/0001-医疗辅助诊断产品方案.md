# 医疗辅助诊断产品方案（v1）

> 本文是**产品与工程方案**，不是进度记录。进度、数字与未验证项各有归口：
> 实测数字进 README，质量问题进 `SECURITY.md`，变更历史进 `CHANGELOG.md`。

## 1. 定位

**kubedocs 是一款面向患者的自助疾病方向检查与辅助诊断产品。**

患者用自然语言描述不适，系统通过**多轮对话式采问**把描述问细，最终给出四件东西：

| # | 交付物 | 说明 |
|---|---|---|
| 1 | **科室建议** | 该挂哪个科（含备选） |
| 2 | **可能病症排序** | 按可能性排序的候选方向，**不是诊断结论** |
| 3 | **检查建议** | 建议做哪些检查 |
| 4 | **用药建议** | 建议考虑哪类药（**不给剂量**） |

外加一条不可省的安全路径：**急诊红线与紧急处理指引**。

底座是 kubedocs 已有的 agent 平台能力（多域协议、混合检索、LangGraph 图、工具协议、
评测闸门、可观测）。**平台不是产品，是产品的地基**；`k8s_docs` 域降为
**RAG 底座与工程验证用域**，不再与医疗域平级出现在产品叙述里。

### 1.1 明确的边界（不做什么）

| 不做 | 理由 |
|---|---|
| **不给剂量** | 那已是处方行为；本项目的目标是技术可行性与工程落地，不是替代医师开方 |
| **不宣称诊断** | 输出一律是"可能方向 + 建议"，结论责任在医师 |
| **不接真实 HIS/EMR/号源** | 暂无系统可对接，只做功能测试（`MockAppointmentProvider` 保持替身地位） |
| **不做法规合规工作** | 按你的定调：本项目用于经验积累，法规风险不在本轮范围 |
| **不深挖多机构** | 本轮只留**占位接口**，不建真实 schema 与隔离机制 |
| **不做"创新算法"** | 原型 `medical-agent` 的"数学化模糊意图 / 量化模糊词 / 永不不知道"不采用：那类设计难以验收、难以维护 |

## 2. 判断由谁做（这是全局最重要的一条）

```
         ┌──────────────────────────────────────────────┐
         │  大模型 = 主判                                │
         │  依据：系统提示词 + 证据包（下面三路）        │
         └──────────────────────────────────────────────┘
                        ▲            ▲            ▲
        ┌───────────────┘            │            └───────────────┐
        │                            │                            │
 ① 急诊判断（模型）           ② 分诊信号                  ③ RAG 检索证据
 （病症 + 严重程度 → `red_flags`）  （检索式，见 §5）        （由模型自调工具取证）
```

- **急诊判断权在模型**（**2026-10-15 架构转向，取代本文早先的"决定 2b"**）：
  模型按**病症 + 严重程度**判断，输出可审计的 `red_flags`
  （`condition` + `severity` + `why`，见 `contracts.RedFlag` 与 `system.md` R1）。
  **关键词红线（`domains/clinic/redline.py`）已退出判断链**：不进提示词、不影响 `urgency`、
  不触发急诊横幅；它只在主判不可用时给一句保守对话提示，并在"命中而模型未判急重症"时留一条不一致痕迹。
  > **为什么改**：词表覆盖不到的表述会漏。实测「胸骨后压榨样疼痛，向左肩放射，伴大汗」
  > （教科书级心梗）在 15 词表下**一个词都不命中**。代价是**没有确定性兜底**——这是明确的取舍，不是疏忽。
  > ⚠️ 图路径（`/chat`、`/patient`）**仍用**关键词强制边，两条路取舍相反，见 `redline.py` 顶部那张表。
- **唯一保留的硬约束是"不许自相矛盾"**：判出 `red_flags` 却把 `urgency` 写成非 emergency ⇒
  契约层记违规（`validate_against`）。判断权可以给模型，"判了急症却给常规建议"不行。
- **分诊是辅助信号**：它给候选科室与置信度，帮模型收敛，但**不替模型下结论**。
- **RAG 是唯一的知识来源**：检查建议与用药建议**只能**来自检索到的资料；
  检索不到就**不给**（按你的决定 5）。这条是硬约束，由契约层校验。
  > 工具循环下这条**依然成立**：证据编号 `K1`、`K2`… 由代码分配，
  > 模型不检索就没有编号可引用，也就给不出检查/用药建议。

## 3. 分层与目录

```
src/kubedocs/
  # ── 底座（已存在，基本不动）─────────────────────────────
  store/ retrieve/ evaluation/ observability/ agent/ domains/ api/
  # ── 产品层（本次新增）──────────────────────────────────
  clinical/
    contracts.py      # 输出契约 + 证据模型（Pydantic，唯一真相）
    evidence.py       # 证据装配：分诊 / RAG → EvidenceBundle（关键词命中已不进上下文）
    rag.py            # 可替换检索后端协议 + 默认适配器
    intake.py         # 结构化采问槽位 + "下一问该问什么"
    prompts/
      system.md       # 系统提示词（**版本化、可 diff、单测锁死**）
      __init__.py
    reasoning.py      # LLM 主判：证据 → 契约化输出（解析 + 校验 + 降级）
    skills/
      base.py         # Skill / SkillStep / SkillRegistry
      booking.py      # 挂号 skill 流程（本次的第一个 skill）
    pipeline.py       # 编排：采问 → 检索 → 证据 → 主判 → 动作 → 应答
    persistence.py    # 患者数据/机构：**占位接口**（本轮不实现）
```

设计原则：

1. **契约先行**：`contracts.py` 是模型输出、前端渲染、评测断言三方共用的唯一形状。
2. **能力封装**：每项能力有明确输入输出协议，互不直接依赖（`rag.py` 不知道 LLM，`reasoning.py` 不知道 HTTP）。
3. **可替换**：RAG 后端、LLM 客户端、持久化都是协议 + 默认实现（按你的决定 3a）。
4. **不新增假开关**：任何配置项必须接在真实分支上，否则不加。

## 4. RAG 后端协议（可替换）

```python
class RetrievalBackend(Protocol):
    name: str

    def search(self, query: str, *, top_k: int, domain: str) -> list[RetrievedChunk]: ...
    def health(self) -> BackendHealth: ...
```

- **默认实现** `LocalIndexBackend`：包住现有 `HybridRetriever`（BM25 + 向量 + RRF），零行为变化。
- **预留** `HttpRagBackend`：本轮只留协议与一个显式抛 `NotImplementedError` 的桩，
  等真实 RAG 系统给出 API 形状再填 —— **不猜**接口。
- 返回的 `RetrievedChunk` 必带 `source_url` / `title` / `score`，供契约层做"引用必须可点"的校验。

## 5. 分诊（指标硬要求：≥ 80%）

**现状**：`agent/hypothesis.py` 里手写权重的证据打分，实测准确率 **0.0**，评测只有 **5 条**用例。

**方案：改成检索式分诊**

1. 用**知识卡片语料**做症状检索（现 31,592 张；原型 `medical-agent` 的 OpenCMKG 派生卡片可作为补充数据源），
   取 top-N 命中卡片的**科室标签投票**，按票数与检索分数加权；
2. 叠加 **别名/层级映射表**（"心内科" ↔ "心血管内科"、口语"心里发慌" ↔ "心悸"）；
3. 输出 top-3 候选科室 + 置信度，进证据包。

**度量先修**：5 条用例上谈 80% 没有意义。分诊金标必须先扩到 **≥ 50 条**
（从知识卡片自动生成候选 → 人工确认），否则"达到 80%"只是一个数字游戏。
这一步是**前置条件**，不是可选项。

### 5.1 语料补充：**有效**（附一次被推翻的结论）

**问题**：31,592 张卡片里，带「建议就诊科室」子句的 27,303 张中有 **12,863 张（47.1%）是「未标注」**。

**根因**（查证过，不是猜测）：`cards.json` 生成阶段**丢掉了关系**——占位符卡片的
`diseases` 字段本身就是「暂无」，所以**在卡片内部做传递补全的成功率是 0%**（实测：
同 key 0 条、经 `diseases` 0 条、经 `drugs` 0 条）。这些卡片是
`耳朵里疼 / 耳朵疼 / 耳朵很疼 / 耳朵特别疼` 这类**口语变体**，在源图谱里根本没有关系。

**做法**：回到原型 `medical-agent` 的原始三元组 `triples.txt`（19 MB，`head,relation,tail`）
重新推导，产出 `data/clinic/department_map.json`（带 `source` + `confidence`，
可抽检、可回退；`scripts/clinic_derive_departments.py` 可重跑）：

| 来源 | 条数 | 占未标注 key | 性质 |
|---|---|---|---|
| `SameAs` 别名归并 | 3,009 | 17.5% | 权威 |
| 最近邻模糊归并（Jaccard≥0.5） | 1,252 | 7.3% | **有错例，需抽检** |
| 实体→疾病→科室 | 466 | 2.7% | 权威 |
| 无解（纯口语变体） | 12,425 | **72.4%** | 需外部标注 |

**效果：口语口径上有效，规范名口径上有小代价。** `eval_triage.py --department-map {off,high,medium}`：

| 档位 | A top-1 | A top-3 | B top-1 | B top-3 | C(5) top-1 | C2(71) top-1 | C2 top-3 |
|---|---|---|---|---|---|---|---|
| off | **164**/200 | 197 | 153/200 | 196 | 2/5 | 35/71 | 48 (67.6%) |
| high | 162/200 | 197 | 153/200 | 196 | 3/5 | **44/71** | **58 (81.7%)** |
| medium | 160/200 | **196** | 153/200 | 196 | **4**/5 | 40/71 | 57 (80.3%) |

⇒ 口语金标 C2 上 top-1 **+12.7 点**、top-3 **+14.1 点**；最有价值的是 `high` 档
（图谱直接关系 + `SameAs` 别名），**模糊档的噪声反而拖后腿**，因此默认只信 `high`。
A 上降 2 例：补全让候选池里的旁观卡片也开始投票，在"查询词就是卡片名"的 A 集里
只会稀释正确卡片的票——这是真实但很小的代价，且 A 是**上限集**。

> **⚠️ 更正留档**：C 只有 5 条时，同一实验给出 `off 2 / high 3 / medium 4`，
> 据此我一度写下"主口径无提升、瓶颈不在语料覆盖率"。**扩到 71 条后结论反转**：
> `medium 4 > high 3` 是噪声，而 +14 点的真实增益在 5 条样本上根本不可见。
> 这正是本节下方"度量先修"那条前置条件的实证：**不做就会读错结论。**

### 5.2 分诊金标 C2：从 5 条扩到 71 条

`scripts/build_triage_gold.py`，依据全部来自原型（不是我编的）：

| 来源文件 | 作用 |
|---|---|
| `data/eval/prototype/department_scope.md` | **科室导诊范围标准**：显式给出「症状 → 科室」判据 |
| `data/eval/prototype/phenomenon_to_symptom.json` | 口语现象 → 规范症状（300 个规范症状及口语变体） |
| `data/eval/prototype/manual_annotation.csv` | 853 条人工实体等价（`标注结果=1`）——**实测对本环节无用**（装的是疾病名等价，如 `妊娠合并糖尿病`↔`妊娠期糖尿病`），零背书 |

构造中**三道质量闸**，每道都是被实际错例逼出来的（详见脚本模块文档）：

1. **部位冲突**：`头痛 -> 乳头疼`（乳≠头）——只按"实义字重合"判它会通过；
2. **多科室归属 / 互为子串**：`胸痛`（呼吸内科+心内科）、`腹痛` 与 `下腹痛`（消化内科+妇产科）一律丢弃，
   金标答案必须唯一；
3. **变体必须对标准文档的关键词也成立**：`月经量少 -> 怕量少` 对前者成立，
   但记成「月经→妇产科」时没人读得出是月经问题；
   同类还有 `眼 -> 干涩感`、`咽 -> 有异物`、`口腔 -> 溃疡面`。

另外`_match_canonical` 从"子串包含"改成**只用前缀匹配**——包含匹配曾让
泌尿科的「绞痛」匹配到规范症状「心绞痛」，造出 `「心绞痛」-> 泌尿科` 这种概念错位的假金标。

`human_verified=false`：答案是标准文档的规则，**未经医学人员逐条复核**，
测的是"对原型标准的符合度"，**不是上线准确率、也不是达标证据**（C2 top-3 81.7% 已越过 80%，
但按上面的限定，**不据此宣布达标**）。

## 6. 挂号系统 → skill 流程

挂号不再是"几个散落的工具"，而是一个**有状态的 skill**：

```
book_appointment (skill)
  step 1  resolve_department   输入：证据包/模型结论  → 输出：目标科室（需明确）
  step 2  list_candidates      查询号源              → 输出：可约的时间段列表
  step 3  confirm              向患者复述并等待确认   → 需要显式确认（沿用现有 interrupt 语义）
  step 4  commit               落库                 → 输出：预约号
  step 5  receipt              给患者可核对的凭据
```

- 每步声明：**输入契约、输出契约、是否产生副作用、失败如何回退**。
- `commit` 是唯一有副作用的步骤；未确认**绝不**执行（现有图里"挂号必须显式确认"的性质保留）。
- skill 注册进 `SkillRegistry`，可被列举（`GET /skills`），编排器按名字取用，不硬编码 import。

## 7. 工作流规范

一条主链，节点职责单一：

```
intake ──▶ retrieve ──▶ evidence ──▶ reason ──▶ act ──▶ respond
  │            │            │           │         │        │
  │            │            │           │         │        └ 按契约渲染患者可读文本
  │            │            │           │         └ 需要动作时派发 skill（挂号）
  │            │            │           └ LLM 主判 → 契约化输出（校验/降级）
  │            │            └ 分诊 + 检索命中 → EvidenceBundle（关键词命中不进上下文）
  │            └ 调 RAG 后端（可替换）
  └ 检查槽位缺口 → 决定"继续追问"还是"可以给结论"
```

两条硬规则（**按 2026-10-15 的架构转向更新**）：

- **证据不足不得给结论**：槽位缺口存在时走追问分支，不硬凑答案。
  > 有工具循环时**追问由模型决定**（R5）：闸门抢在模型之前会拦住急症——
  > 实测教科书级卒中「突发言语不清，右侧肢体无力两小时」曾被 4/4 次回成一句追问。
- **判出急重症不得普通应答**：`red_flags` 非空而 `urgency` 不是 `emergency` ⇒ 契约层记违规。
  （早先这条写作"红线阳性不得普通应答"——判断依据已从关键词改为模型的 `red_flags`，
  两者**不再等价**：图路径上红线仍是强制边，临床管线上它只是降级提示与不一致痕迹。）
